# Write Natural English Post

把中文作者想说的话，重新组织成英语读者能自然阅读的独立帖子。目标是像作者本来就用英语写作，既不逐句搬运中文，也不把作者改造成另一种人。自然表达优先于字面对齐，意思忠实优先于文案效果。

## 输入与默认处理

本技能用于独立发布的内容。英文材料可以作为参考，出现英文不代表是在回复它；用户明确要回应某条帖子或消息时，应按回复任务处理。若只安装了本技能，仍需按实际写作目的处理，不假设其他技能可用。

“更口语化”“不要翻译腔”“再短一点”是表达调整要求，不单独决定技能选择。同一任务的后续修改沿用当前技能；用户明确改变写作目的时再切换。只有无法从上下文确定写作目的且会影响成稿时，才询问是独立发帖还是回应他人。

- 必需输入只有中文帖子或中文发帖想法，不要求提供英文原帖。若正文已在上下文中，直接使用。
- 平台、受众、长度、英语地区和语气均为可选信息。未指定时，使用常见、地区色彩较弱的自然英语，保留原文的正式程度与篇幅规模，不为这些信息逐项提问。
- 如果用户只是说要翻译而没有给内容，只询问中文内容。只有歧义会实质改变立场、事实或指代时才澄清；其他情况采用稳妥措辞。
- 识别原文是随手感想、经验分享、提问、观点讨论、故事还是产品介绍。不要把所有帖子都写成短评论，也不要把个人分享改成推广文案。

## 后续修改

- 以用户指定的版本为基础；未指定时，使用最近一版成稿并保留用户已接受的调整。只修改本次要求涉及的部分及必要的衔接，不顺带重写其他内容。
- 仍以原始中文和用户后续明确修订核对含义；二者冲突时，以用户的新修订为准。输出回译与分析时，同步更新为本次英文实际表达的内容。
- 用户要求“只要英文”后，同一写作任务的后续修改沿用该格式，直到用户另有要求。

## 改写流程

1. 提取必须保留的内容：主要观点、具体细节、叙事先后、因果关系、情绪强度、确定程度，以及作者希望读者回答的问题。
2. 判断哪些内容依赖中文语境或前文。独立帖子需要能够自行读懂，只补足原文中可确定的指代；不能猜测被省略的人物、事件或背景。
3. 暂时放下中文句式，按英语的信息顺序重新写作。可以拆句、合句、调整段落或删去纯粹重复，但不得删掉理由、限定条件、例外或有意义的细节。
4. 根据原文声音和发布场景调整词汇、节奏与段落。短想法保持短，长叙事保留发展过程；不机械追求中英文相同字数。
5. 对照原文检查意思，再把英文当作独立帖子通读。修复需要读者“猜中文原句”才能理解的表达，以及过度工整、过度解释或语气失真的地方。
6. 对最终英文进行中文回译和读者视角审查。发现可修复问题时先修改英文，再同步更新回译与审查，不展示中间草稿。

## 保留作者，而不是润色成模板

- 保留第一人称、个人判断和情绪中的分寸。“感觉”“可能”“暂时”“对我来说”不能被改成普遍事实；温和不满不能升级为愤怒，明确批评也不要被自动软化。
- 不增加用户没有说过的经历、数字、结果、承诺、推荐、赞美或结论。不凭空添加吸引眼球的开头、互动问题或行动号召。
- 常用词和自然搭配通常更好；缩写形式如 `I'm`、`don't` 适用于随意语气，但正式原文不必强行口语化。
- 保留原文有意义的重复、停顿、自嘲和个性。自然不等于一律缩短，也不等于给每句话加俚语。
- 不用刻意的语法错误、拼写错误、全小写、粗口或网络黑话假装真人。只有作者原本的声音或明确要求支持时才采用这些风格。

## 处理中文表达

- 中文惯用语、网络词和比喻，先判断它在句中表达的功能，再选择自然英文。没有贴切对应时，用朴素表达保留意思，不硬套英语梗。
- 对“折腾”“上头”“离谱”“卷”等多义词，按具体语境理解，不固定翻成某个英语词。
- 中文常用的“其实”“不得不说”“总的来说”等，判断是否承担转折、强调或总结作用；没有实际作用时可以省去，不逐个补成英文连接词。
- 中国特有的概念或事件，只加入原文支持且理解所需的最短说明。无法确定的含义应澄清，不能自行编背景。
- 保留专有名词、产品名称、版本、数字、链接和技术含义。英语术语使用通行写法，不为口语感牺牲准确性。

## 消除翻译腔和模板化 AI 文风

优先检查以下问题，而不是把某个单词或标点当作 AI 的证据：

- 中文语序、悬空主语、连串抽象名词，或语法正确但在当前语境中不自然的搭配。
- 不必要的开场白，例如 `In today's fast-paced world`、`It is worth noting that`，以及重复陈述中心思想的结尾。
- 把普通感想写成演讲、营销或励志文案；自动加入“改变一切”“彻底颠覆”等夸张措辞。
- 反复使用三项排比、相同句长、对称转折或 `It's not about X. It's about Y.` 一类模板。
- 为了显得流畅，添加原文不存在的逻辑关系、因果推断或意义升华。
- 用太多破折号、感叹号、标题或项目符号制造节奏。标点按实际需要使用，不机械禁用。

修改时优先换成具体、直接的说法，调整信息顺序，删去空话。

## 平台适配

- **X/Twitter**：开头直接进入内容，段落紧凑；不要默认添加 hashtag、emoji 或拆成串帖。有明确字符上限时按上限调整，不为压缩而丢失关键限定。
- **Reddit／论坛**：保留理解问题所需的背景、经历和具体问题。仅在版块惯例或用户要求支持时添加标题，不擅自加 TL;DR。
- **专业社交平台**：可以更完整、有条理，但避免企业宣传语和虚构的职业启示。
- **未知平台**：给出普通独立帖正文，不擅自添加平台格式、标题、标签或互动引导。

遇到明确的字符或字数上限，先压缩冗余表达，再核对最终英文的长度与含义。若仍无法同时满足上限和关键信息保留，简短说明冲突，询问允许删减哪些内容或是否拆分；用户已授权删减或拆分时，按其要求处理。不要悄悄删除关键限定，也不要把超限稿标为符合要求。即使用户要求“只要英文”，必要的冲突澄清也应先完成。

已有 emoji、标签和格式可按原意保留；用户要求优先于上述默认值。该技能负责撰写，不自动发布。

## 输出

默认提供一版成稿和简短中文说明：

**英文帖子**

输出可直接复制的完整英文，不加包裹全文的引号。若环境支持可复制的写作块，可将英文成稿放入其中；回译与分析放在块外。

**中文回译**

忠实回译最终英文实际表达的含义，不直接复述原始中文，以便用户发现语气或含义的偏移。

**英语读者视角**

审查最终英文的具体表达，不推断作者身份或检测结果。说明读者在当前语境下可能如何理解，并引用影响判断的措辞；不把所有英语读者视为意见一致的群体。正式表达、常见词或某种标点本身不构成翻译或 AI 痕迹。可修复的问题先修改；无法消除且影响理解的歧义或语气风险应简短说明。不承诺通过检测或无法被识别。

- 理解与感受：读者最可能读出的观点、态度与语气。
- 自然度：结合具体措辞或句子节奏说明，不套用泛泛赞美。
- 翻译／AI 痕迹：评估生硬搭配、冗余解释或模板化表达。没有明显问题时简短说明，不必重复泛泛赞美；有问题时指出具体位置和影响。

分析长度与帖子规模相称，短帖只需几句。默认不提供多个版本；用户要求时再给有明确差异的版本。用户说“只要英文”“直接给我能复制的”或“不要解释”时，只输出最终英文成稿。

## 示例：自然重写，但不制造内容

中文：最近又开始折腾 Linux 了。忙活了一晚上，结果只是换了个主题。但还挺开心的。

英文：I've been tinkering with Linux again lately. Spent the whole evening on it and all I ended up doing was changing the theme. Had fun, though.

这里用 `tinkering` 表达这一语境下的“折腾”，用自然省略和末句保留自嘲；不编造修系统、提升效率等经历。

中文：用了几天 Vite，感觉还行，但暂时不会用在生产环境里。

英文：I've been using Vite for a few days, and it seems decent so far. I won't be using it in production for now, though.

这里用原文提供的工具名明确指代，并保留“几天”“感觉”“暂时”的限制。后一句表达当前的使用决定，不推断作者尚未准备好，也不将个人选择改写成工具不适合生产环境的客观结论。若原文只说“正式项目”，应根据上下文判断具体含义，不固定译成 `real project` 或 `production`；工具名缺失且影响独立阅读时，询问名称，不虚构。

### 保留不确定程度与测试范围

中文：Vite 目前看起来快一些，但我只在一个小项目里测过。

英文：Vite seems a bit faster so far, but I've only tested it on one small project.

保留点：`seems`、`so far` 和 `one small project` 分别保留判断的不确定程度、时间范围与测试范围，不将个人观察写成普遍性能结论。这只是成稿示例，实际输出仍遵循默认格式或用户要求。

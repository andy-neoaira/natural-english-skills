# Natural English Skills

面向中文用户的两个 Agent Skills：将中文帖子或回复意图改写为自然英文，保留原本的观点、细节与语气。

适用于 X / Twitter、Reddit、技术论坛、社群和普通英文聊天。默认提供 **英文成稿、中文回译和读者视角审查**，帮助你确认英文实际表达的含义，以及读者可能感受到的语气。

## 选择技能

| 你想做什么 | 使用哪个 Skill | 需要提供什么 |
| --- | --- | --- |
| 写一篇独立的英文帖子、分享或提问 | [write-natural-english-post](write-natural-english-post/SKILL.md) | 中文正文或发帖想法 |
| 回复已有的英文帖子、评论或消息 | [write-natural-english-reply](write-natural-english-reply/SKILL.md) | 英文原帖 + 中文回复意图 |

按写作目的选择：**独立发帖用 post，回应他人用 reply**。英文资料可以只是发帖参考，不代表要回复它。上下文中已经提供的内容无需重复粘贴。

“更口语化”“不要翻译腔”“再短一点”等后续调整沿用当前任务；明确要求“把这条回复改成独立帖子”时，再切换写作目的。只有目的不清楚且会影响成稿时，才需要澄清。

## 安装

本仓库只包含技能说明文件，无需构建或安装项目依赖。你需要一个支持加载 `SKILL.md` 的 Agent；技能的安装目录和启用方式以所用 Agent 的文档为准。

### 克隆并复制

下面以 `~/.agents/skills/` 为目标目录，命令适用于 macOS / Linux。若你的 Agent 使用其他目录，请替换对应路径。

```bash
git clone https://github.com/andy-neoaira/natural-english-skills.git
mkdir -p ~/.agents/skills
cp -R natural-english-skills/write-natural-english-post ~/.agents/skills/
cp -R natural-english-skills/write-natural-english-reply ~/.agents/skills/
```

两个技能彼此独立，只需要其中一个时，执行对应的复制命令即可。若目标目录已有同名技能，复制会覆盖其中的同名文件；有本地修改时请先备份。

安装后的目录结构：

```text
~/.agents/skills/
├── write-natural-english-post/
│   └── SKILL.md
└── write-natural-english-reply/
    └── SKILL.md
```

也可以下载仓库 ZIP，解压后将需要的技能目录完整复制到目标位置。保持“技能目录 → `SKILL.md`”这一层级。

### 确认加载

按所用 Agent 的方式重新加载技能或开启新会话，并确认它能发现对应技能。随后可以直接描述需求，也可以在请求中明确写出技能名。

如果技能没有被识别，先检查目标目录、目录层级，以及该 Agent 的技能加载设置。

## 使用示例

不要求固定的提示词模板。以下示例中的英文用于展示写作风格，实际措辞会随上下文变化。

### 写英文帖子

输入：

```text
使用 write-natural-english-post，把下面这段中文改成适合发到 X 的自然英文：

最近又开始折腾 Linux 了。
忙活了一晚上，结果只是换了个主题。
但还挺开心的。
```

英文成稿示例：

> I've been tinkering with Linux again lately. Spent the whole evening on it and all I ended up doing was changing the theme. Had fun, though.

这里用 `tinkering` 表达“折腾”，保留忙活一晚只换了主题的自嘲和乐趣。默认还会提供中文回译与英语读者视角审查。

平台、受众、长度、英语地区和语气都是可选信息。未指定时，post 使用常见、地区色彩较弱的自然英语，并保留原文的正式程度与篇幅规模。

### 写英文回复

输入：

```text
使用 write-natural-english-reply，帮我写一条自然英文回复。

英文原帖：How long would you keep building before your first paying customer?
中文回复：说实话，我不知道。不过不试试怎么能知道结果呢。
```

默认输出示例：

**英文回复**

Honestly, I have no idea. But there's only one way to find out.

**中文翻译**

说实话，我完全没概念。但想知道结果，只有去试这一条路。

**母语者视角**

- 理解：没有给出具体时间，表达的是“只有试了才知道”。
- 感受：坦诚、轻松，带一点鼓励。
- 自然度：`there's only one way to find out` 在这里承接了继续尝试的语境；“去试”的意思由上下文补足。
- 翻译 / AI 痕迹：没有明显的生硬搭配或模板化铺垫。

reply 也支持不带标签的输入：先放英文原帖，再用两个空行隔开中文回复。所需内容在上下文中也找不到时，技能只询问缺少的部分。

### 只要可复制的英文

在请求中加上：

```text
只输出最终英文，不要回译和分析。
```

同一写作任务的后续修改会继续沿用这个偏好，直到你另有要求。

需要不同语气的备选时，可以明确要求，例如“给我两个版本：一个更随意，一个更专业”。默认只提供一版成稿。

### 继续修改成稿

可以直接针对上一版提出调整：

```text
保留上一版开头，把最后一句改得更克制一点。只要英文。
```

也可以指定更早的版本。技能会以指定版本为基础；未指定时使用最近一版，保留已接受的调整，只修改本次要求涉及的部分及必要衔接。需要回译和分析时，它们会同步更新为最终英文的含义。

### 指定语气与长度

例如：

```text
这是给客户的正式回复，请保留“目前无法承诺”的语气。
```

```text
把这段帖子写成不超过 200 个英文字符的版本，包含空格。保留测试范围和不确定程度。
```

原文正式时保持正式，明确批评不自动软化。reply 按中文回复的信息量决定篇幅，不因原帖只有一句话而删掉理由或例外。

有明确长度上限时，先压缩冗余；如果仍无法同时保留关键信息并满足上限，会询问允许删减哪些内容或是否拆分。即使要求“只要英文”，这类必要的冲突澄清仍可能出现。

## 默认输出

| 内容 | post | reply |
| --- | --- | --- |
| 可直接复制的英文成稿 | 英文帖子 | 英文回复 |
| 最终英文实际表达的中文含义 | 中文回译 | 中文翻译 |
| 对理解、语气、自然度及翻译 / AI 痕迹的审查 | 英语读者视角 | 母语者视角 |

中文回译针对的是**最终英文**，方便你检查含义或语气是否发生偏移。读者视角结合具体措辞说明可能的理解和感受，不能代表所有英语读者；没有明显问题时简短说明，有残留歧义或语气风险时指出具体影响。

## 写作原则与范围

- **保留意思与分寸**：保留观点、理由、技术细节和情绪强度；“感觉”“可能”“暂时”等限定也需要保留。
- **按英语习惯组织表达**：允许调整语序、拆句、合句或使用贴切的固定说法。习语只有在保留原意、语气和限定时才适用，普通直接表达同样可以很自然。
- **保留作者的声音**：明确要求优先；未指定时保留原文的态度、情绪强度和正式程度。reply 在原文没有明确风格时，采用简洁、直接、自然的表达。
- **不补造内容**：不自行添加经历、数据、事实、立场、承诺或推广话术。
- **检查可观察的表达问题**：关注生硬搭配、冗余铺垫、模板化句式等。正式表达、常见词或某种标点本身不构成 AI 痕迹，不承诺通过检测或无法被识别。

技能负责撰写内容，不会自动发布。生成结果仍需要你核对是否准确表达了自己的意思。
